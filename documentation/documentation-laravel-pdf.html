Documentación técnica · sodeker/laravel-pdf

Paquete de generación de PDF

sodeker/laravel-pdf convierte vistas Blade de la aplicación en archivos PDF usando Browsershot y Chromium. Se instala con Composer en cualquier aplicación Laravel 12 de Sódeker. No trae diseños propios: cada aplicación pone su maqueta, su encabezado y su pie.

Cómo está construido

Un contrato compartido, un servicio que renderiza Blade y un puerto intercambiable que convierte HTML en PDF.

ComponenteResponsabilidadUbicación
GeneratePdfContractFrontera pública. Es lo único que importan los demás módulos.src/Contracts
GeneratePdfFromViewServiceCaso de uso: valida todas las vistas, las renderiza con la misma data y llama al puerto de conversión. No depende de Laravel.src/Application/Services
TemplateRendererPuerto de salida: convierte una plantilla y su data en HTML.src/Application/Ports
BladeTemplateRendererImplementación con Blade (ViewFactory de Laravel).src/Infrastructure/Templates
HtmlToPdfRendererPuerto de salida: recibe HTML ya renderizado y devuelve el binario del PDF.src/Application/Ports
BrowsershotHtmlToPdfRendererImplementación con Browsershot. Traduce las opciones de página a Chromium y le indica dónde guardar su perfil (pdf.temporary_directory).src/Infrastructure/Renderers
PdfServiceProviderRegistra el contrato y el renderer, y publica config/pdf.php. Laravel lo descubre solo.src/
PdfPageOptionsDTOFormato, orientación, márgenes en mm y timeout.src/Application/DTOs
GeneratedPdfDTOResultado: contenido binario, nombre del archivo, tamaño y base64.src/Application/DTOs
ExcepcionesPdfTemplateNotFoundException y PdfRenderingFailedException, ambas hijas de PdfGenerationException. Son fallos del caso de uso, no reglas de negocio.src/Application/Exceptions
PageFormat / PageOrientationEnums: Letter, Legal, A4 y vertical/horizontal.src/Domain/ValueObjects

Puerto y adaptador

El servicio depende de dos puertos, TemplateRenderer y HtmlToPdfRenderer, no de Blade ni de Browsershot. Cambiar a otro motor (por ejemplo Gotenberg) es escribir otra clase y registrarla: el provider usa bindIf, así que la aplicación puede poner la suya sin tocar el paquete.

Contrato compartido

Los módulos consumidores nunca importan el servicio. Piden GeneratePdfContract al contenedor de Laravel. Lo interno del paquete puede cambiar en una versión menor sin romperlos.

Sin estado

El servicio se registra como singleton (una sola instancia por petición) porque no guarda nada entre llamadas.

Uso

Cómo pedir un PDF

Se inyecta el contrato y se llama a generate() con argumentos nombrados. Solo view es obligatorio.

PHP · módulo consumidor
use Sodeker\Pdf\Contracts\GeneratePdfContract; use Sodeker\Pdf\Application\DTOs\GeneratedPdfDTO; public function __construct(private readonly GeneratePdfContract $pdfGenerator) {} $pdf = $this->pdfGenerator->generate( view: 'pdf.studies.show', data: $data, header: 'pdf.shared.header', // opcional footer: 'pdf.shared.footer', // opcional fileName: 'resultado-estudio', // opcional, se agrega .pdf ); return response($pdf->content, 200, [ 'Content-Type' => GeneratedPdfDTO::MIME_TYPE, 'Content-Disposition' => "inline; filename=\"{$pdf->fileName}\"", ]);

Encabezado y pie

Vistas reutilizables de la aplicación

El encabezado y el pie viven en la aplicación, por ejemplo en resources/views/pdf/shared/, y cualquier PDF de esa aplicación los puede reutilizar.

Estilos en línea

Chromium renderiza el encabezado y el pie en un documento aparte: no ven el CSS del cuerpo ni cargan hojas externas.

Imágenes como data URI

Logos y firmas se incrustan como data:image/...;base64. Una URL, incluso una de S3, no se descarga en esa zona.

Tamaño de letra explícito

Sin font-size declarado, el texto sale diminuto. Declara siempre el tamaño en cada elemento.

Instalación y configuración

Qué necesita para funcionar

El paquete trae el código PHP. Node, puppeteer y Chromium los pone el servidor donde corre PHP: sin ellos, el paquete se instala pero no genera nada.

Instalar en una aplicación

1Declarar el repositorio privado en composer.json
"repositories": [ { "type": "vcs", "url": "git@github.com:Sodeker-SAS/laravel-pdf.git", "no-api": true } ]
Mismo patrón que doma-composer: Composer clona por SSH con la llave de cada desarrollador. Si la aplicación ya declara otros repositorios, se agrega uno más al arreglo.
2Instalar el paquete
composer require sodeker/laravel-pdf
Trae spatie/browsershot ^5 como dependencia. Laravel descubre PdfServiceProvider solo: no hay que registrarlo en bootstrap/providers.php.
3Instalar puppeteer
pnpm add puppeteer PUPPETEER_SKIP_DOWNLOAD=true # si la imagen ya trae Chromium
Puppeteer es la pieza de Node que controla Chromium. Si la imagen PHP ya instala Chromium, no hace falta que puppeteer descargue otro navegador.
4Hacer visible node_modules para el contenedor php
php: volumes: - ./:/var/www - node_modules:/var/www/node_modules
Browsershot lanza Node desde el contenedor php, y ahí tiene que encontrar puppeteer. Si las dependencias solo viven en el volumen del contenedor node, falla con Cannot find module 'puppeteer'.
5Publicar la configuración (opcional)
php artisan vendor:publish --tag=pdf-config
Solo si la aplicación necesita algo que no se resuelve con variables de entorno. Sin publicar, el paquete usa su propio config/pdf.php.

Configuración

Todo se lee de config/pdf.php. Las variables de entorno son las mismas que usaba el módulo cuando vivía dentro de FINTEGRA, así que un .env existente sirve sin cambios.

●

El perfil de Chromium vive en el directorio temporal

Chromium guarda su perfil (.config, .cache, .local) en el directorio personal del usuario. Bajo PHP-FPM ese usuario es www-data, cuyo directorio suele ser la raíz del proyecto, y ahí aparecían esas carpetas. El renderer le pasa a Chromium las rutas XDG apuntando a {temporary_directory}/{config,cache,data}. No se usa HOME porque Browsershot le da prioridad al entorno del proceso y lo sobrescribe.

Por dentro

Marca de agua y pie: dos mecanismos distintos

Los dos se repiten en cada página, pero por caminos diferentes. Entenderlo evita pasarle al paquete algo que no necesita y viceversa.

Marca de agua: HTML del cuerpo con position: fixed

Un parcial de la aplicación (por ejemplo pdf.shared.watermark) se incluye una vez en el cuerpo. Al imprimir, Chromium dibuja los elementos con position: fixed en todas las páginas, en la misma posición. z-index: 10 la pone encima de las tarjetas y opacity: .05 la deja tenue. El texto de debajo sigue siendo seleccionable. No es parámetro del paquete porque no necesita ningún trato especial de Chromium.

Pie: plantilla que Chromium imprime en el margen

El paquete le pasa el HTML del pie a Browsershot (footerHtml con displayHeaderFooter). Browsershot se lo entrega a Chromium, y Chromium lo imprime dentro del margen inferior de cada hoja. Al hacerlo, reemplaza el contenido de <span class="pageNumber"> y <span class="totalPages"> por los números reales. Por eso el pie sí es parámetro del paquete: es la única forma de numerar páginas.

Soporte

Cuando un PDF no sale bien

Los problemas más probables, explicados sin jerga: qué se ve, por qué pasa y qué hacer.

"La plantilla blade [...] no existe"
Qué pasóEl sistema no encontró el diseño del documento, del encabezado o del pie. El mensaje dice cuál.
Por quéEl nombre de la vista está mal escrito, o el archivo se movió o se borró.
Qué hacerPasar el nombre exacto al desarrollador. Es un error de código, no de datos: no se arregla reintentando.
"No fue posible generar el PDF: ..."
Qué pasóEl diseño estaba bien, pero el programa que "imprime" el PDF (Chromium) no pudo arrancar o no terminó a tiempo.
Por quéLo más común: puppeteer no está instalado o PHP no lo encuentra (Cannot find module 'puppeteer'), la ruta de Chromium es incorrecta, o el documento tardó más de 60 segundos.
Qué hacerRevisar el log de Laravel buscando "Error al generar PDF con Browsershot": ahí está el motivo real. Si el mensaje menciona puppeteer, revisar la sección de configuración.
El pie o el encabezado salen diminutos, cortados o no aparecen
Qué pasóEl documento se generó, pero las franjas de arriba o de abajo se ven mal.
Por quéEl margen es más pequeño que la franja, falta el tamaño de letra, o el diseño usa estilos o imágenes externas que esa zona no carga.
Qué hacerAumentar el margen correspondiente y revisar las tres reglas de la sección "Encabezado y pie".
Un logo o una firma no se ven
Qué pasóEl PDF sale, pero con el espacio de la imagen vacío.
Por quéLa imagen se referenció como URL. Chromium no tiene la sesión del usuario ni permiso para leer archivos privados, por ejemplo en S3.
Qué hacerLa aplicación tiene que incrustar la imagen como data URI antes de llamar a generate().
Aparecen carpetas .cache, .config o .local en la raíz del proyecto
Qué pasóDespués de generar un PDF desde el navegador aparecen carpetas nuevas sin seguimiento en git.
Por quéEs el perfil de Chromium. El paquete lo envía al directorio temporal (BROWSERSHOT_TEMPORARY_DIRECTORY, por defecto storage/app/browsershot). Si vuelve a pasar, esa ruta no es escribible o se está usando una versión vieja del módulo.
Qué hacerBorrar esas carpetas (se regeneran solas en su lugar correcto) y revisar que el directorio temporal exista y PHP pueda escribir en él. Una carpeta .config/psysh es distinta: es el historial de tinker.
"Host key verification failed" al ejecutar composer
Qué pasóComposer no puede descargar el paquete privado de Sodeker desde GitHub.
Por quéEl contenedor no reconoce a GitHub. Pasa si la imagen php no tiene la huella de GitHub en known_hosts.
Qué hacerAgregar la huella con ssh-keyscan -t ed25519 github.com en el Dockerfile, reconstruir la imagen y recrear el contenedor. Si el error dice "Permission denied", el problema es la llave personal: revisar ssh-add -l en el computador.
"Class App\Shared\Contracts\PdfGeneration\GeneratePdfContract not found"
Qué pasóDespués de instalar el paquete, una pantalla que genera PDF deja de funcionar.
Por quéSe borró el módulo viejo de la aplicación, pero algún archivo sigue pidiendo el contrato con su dirección antigua.
Qué hacerBuscar App\Shared\Contracts\PdfGeneration y App\Modules\PdfGeneration en el código y reemplazarlos por Sodeker\Pdf\… (ver "Migrar desde el módulo interno").
